# Solver_demo_project 对接 Planner 的开发阶段与验收门禁

**文档编号：** APR-INT-PLAN-001  
**版本：** V1.0  
**状态：** 开发执行基线  
**发布日期：** 2026-08-25  
**适用项目：** `Solver_demo_project` 前端、数据管理与 `planner` 求解引擎集成

> 本文档用于指导实施、阶段评审和最终验收。各阶段只有在对应硬门禁全部通过并留存证据后，才允许进入下一阶段。实现与本文档冲突时，应先更新本文档和受影响的验收项，不得在代码中形成未记录的产品决策。

相关需求依据：[自主路径探索双引擎验证需求基线](./自主路径探索双引擎验证需求基线.md)。

## 1. 目标与实施边界

本次改造从 `Solver_demo_project` 的 Git 提交 `9214a41329c8398f8e7ea3f7d92d18e989f5980f` 建立独立工作树，以 Planner 场景结构作为共享数据契约，完成以下目标：

1. 同一份场景数据能够运行旧求解引擎、Anytime A* 和 GA。
2. 数据管理围绕活动、活动包、资源、事件和场景目标进行简化。
3. 活动、活动包及其输出状态、镜像状态包的技术 ID 全部由系统创建。
4. 网络编辑器只显示可执行活动节点；活动包只作为可折叠容器，状态和状态包不作为画布节点。
5. 活动包与隐藏状态包保持两级层次的一一镜像，活动多包复用时状态成员同步复用。
6. 不引入知识库版本、Revision、Manifest、变更历史、回写、升级和相关页面。

本期只承诺两套引擎都能解释的公共能力：显式状态、`required/transition` 前置、活动输出、工期、容量资源、固定外部事件、串并行模式、场景及活动实例数上限。工作日历、资源实例、数值效果、可消耗物料、抢占和知识版本管理不进入本期。

### 1.1 资源实例排除说明

本期的“容量资源”只表达某类资源在同一时刻可被占用的总数量，例如“技术员容量 3”。“资源实例”则指容量背后可被具体指派的人员、设备或工装，并通常携带资质、型号、班次日历、位置、可用窗口、切换成本和任务绑定。若加入资源实例，旧引擎、A*、GA、统一 Validator、数据导入和结果页面都必须同时增加实例选择与排他约束；只改其中一层会破坏“三引擎解释同一输入”的本期硬门禁。

因此本期已确认不支持资源实例，只支持汇总容量。能力接口必须明确返回 `resource_instances_supported: false`，页面使用“不分配具体资源实例”的业务提示，导入或迁移发现实例级约束时必须阻断或形成报告，不得把它静默折算成汇总容量。

## 2. 门禁规则

### 2.1 门禁等级

| 等级 | 含义 | 处理规则 |
|---|---|---|
| G0 硬门禁 | 数据正确性、兼容性或发布安全要求 | 任一失败即停止进入下一阶段，不允许以人工说明替代 |
| G1 质量门禁 | 可维护性、体验或非关键性能要求 | 必须修复；确需延期时应登记责任人、风险和关闭版本 |
| G2 观察项 | 不阻断本期交付的趋势数据 | 留存结果，供下一阶段优化，不得包装成已满足能力 |

### 2.2 通用通过条件

每个阶段评审必须同时提交：

- 对应提交号、测试命令、完整测试结果和失败项说明；
- 数据库迁移的升级、回退或恢复验证记录；
- 受影响接口的请求/响应样例；
- 涉及界面的关键路径截图或端到端测试报告；
- 已知限制、遗留风险以及是否影响下一阶段的明确结论。

以下情况一律判定为门禁失败：

- 自动化测试存在未解释失败、被临时跳过或通过降低断言规避问题；
- 客户端可以维护系统技术 ID、主输出状态 ID 或镜像状态包；
- 同一场景在不同引擎入口被转换成不同业务含义；
- 网络画布重新出现状态节点或把活动包当成可执行任务；
- 出现知识版本、Revision、Manifest、历史回写或升级入口；
- 数据迁移静默丢失或改写无法适配的旧数据。

## 5. P1：共享场景数据底座与自动 ID

### 5.1 工作内容

- 新建以 Planner `Scenario` 为权威的数据表、领域对象和服务层，不再让旧 `ActivityNode/AtomicActivity/StateNode/OpRule` 成为新场景的权威写模型。
- 场景保存初始状态、目标/禁止状态、目标活动、执行模式、预算、资源、事件和来源信息。
- 创建活动时在同一事务中生成：
  - `activity:<uuid4>` 技术 ID；
  - 场景内递增展示编号 `ACT-0001`；
  - `state:<同一uuid>:output` 主输出状态；
  - 默认名称“活动名称 + 完成”。
- 活动名称修改时，仅在输出状态名称未被显式定制的情况下同步默认名称；技术 ID 和展示编号永不改变。
- 创建种子状态、事件状态及关系记录时同样自动生成技术 ID。
- 活动创建接口拒绝客户端提交 `id`、`display_code` 和主输出状态 ID；导入接口按单独规则处理稳定往返 ID。
- 建立统一结构校验：未知引用、悬空前置、非法工期、资源超量、冲突目标、非里程碑活动缺少 `transition` 前置、不可达目标和实例上限。

### 5.2 Gate P1：数据闭环（G0）

- 并发创建活动不会产生重复 UUID 或展示编号；允许编号因事务回滚出现空洞，不允许重新编号。
- 活动改名、编辑、复制和删除均符合身份规则；复制必须产生全新活动和输出状态身份。
- API 和普通 UI 中不存在技术 ID 输入框，恶意提交技术 ID 返回稳定的 4xx 错误。
- 一个场景完成创建、读取、修改、校验和删除闭环，事务失败不会留下孤立输出状态。
- Planner 原生示例可由数据库对象无损构造并通过现有加载器、模拟器和校验器。
- 数据库升级和恢复验证通过，且不修改基线旧表中的现有数据。

**门禁证据：** 数据模型图、API 契约、并发测试、事务回滚测试、Planner 场景往返测试。

## 6. P2：活动包与隐藏状态包镜像

### 6.1 工作内容

- 创建活动包时自动生成：
  - `activity-package:<uuid4>`；
  - 展示编号 `AP-0001`；
  - `state-package:<同一uuid>` 镜像状态包。
- 活动包采用固定两级结构：一级包只包含二级包，二级包引用活动；包到包只有一个父级，活动可以被多个二级包引用。
- 镜像状态包不提供独立创建、编辑、移动或删除接口。活动包改名、换父级和删除时，镜像状态包在同一事务中同步。
- 添加活动成员时，将其主输出状态引用到对应镜像状态包；移除成员时仅删除两侧成员引用，不删除活动或状态本体。
- 同一活动多包复用时，保留一个 canonical 活动和一个主输出状态，生成多个活动成员引用和状态成员引用。
- 选择一级或二级活动包作为目标时，递归展开所有启用成员活动的主输出状态，按 canonical 状态 ID 去重并以 AND 方式加入目标。
- 活动包用于求解范围时，只在请求边界展开为明确的 canonical 活动 ID，包本身不得进入计划步骤。

### 6.2 Gate P2：包语义一致（G0）

- 活动包与状态包数量、层级、父级和名称一一对应，不存在无镜像、重复镜像或孤立镜像。
- 添加、移除、多包复用、包改名和父级调整的镜像更新均为原子事务。
- 同一活动属于两个包时，数据库只有一个活动本体和一个主输出状态；两个引用可独立排序和布局。
- 一级包目标能够递归展开；同一活动经多条包路径只生成一个目标状态。
- 空包、循环层级、活动直接加入一级包、跨场景引用和隐藏状态包直接写入均被阻止并返回稳定错误码。
- 包成员变化不会隐式修改活动前置、工期、资源需求和附加输出。

**门禁证据：** 包镜像一致性检查报告、层级和多包复用测试、目标展开快照、异常接口测试。

## 7. P3：简化数据管理与活动-only 网络编辑器

### 7.1 工作内容

- 将新数据管理入口收敛为：场景配置、活动包与活动、资源与事件、网络编辑器、校验、导入导出。
- 活动表单只要求业务字段；自动 ID、主输出状态和隐藏状态包以只读摘要显示或完全隐藏。
- 网络画布中：
  - 活动是唯一可连线节点；
  - 活动包是可折叠的两级容器，不是节点；
  - 状态、状态包、事件和资源均不创建画布节点；
  - 同一活动在多个包中以多个显示引用出现，但共享 canonical 身份；
  - 活动 B 的前置状态由活动 A 产出时，投影为 `A→B`，边保留隐藏状态 ID 和 `required/transition`；
  - 种子或事件前置通过活动徽标和详情呈现；
  - 多提供者显示多条候选边，但持久化的是一条状态前置语义。
- 延续预览、进入编辑、草稿、统一提交的页面状态机；拖动、连线、包成员调整和表单保存均先进入草稿。
- 循环依赖允许显示，自动布局需识别强连通分量，不能因图中有环崩溃或无限计算。

### 7.2 Gate P3：界面可用（G0）

- 画布响应和 DOM 中不存在 `state` 或 `state_package` 类型的可视节点，活动包也不会被识别为可执行节点。
- 用户无需填写任何技术 ID 即可完成“建包→建活动→配置前置→设为目标→校验”的完整流程。
- 折叠一级/二级包不会改变依赖语义；展开后活动引用位置稳定。
- 多包复用活动在不同容器可独立布局，改名会同步显示，求解身份不重复。
- 删除边、成员或活动前显示真实影响范围；统一提交失败时数据库零写入且草稿保留。
- 预览模式不能产生写请求，取消编辑可以完整丢弃草稿。
- 页面不存在知识版本、Revision、Manifest、历史、回写或升级入口和文案。

### 7.3 Gate P3：体验质量（G1）

- 100 个活动、20 个包的画布首次布局和常规展开操作无明显阻塞，具体时间作为测试环境基线记录。
- 校验错误可以定位到活动、包、边或表单字段，不要求用户理解内部状态 ID。
- 关键工作流在 1366×768 和 1920×1080 下无被遮挡的主要操作按钮。

**门禁证据：** 组件测试、端到端测试、画布类型断言、关键流程截图、性能记录。

## 8. P4：新旧求解引擎接入

### 8.1 工作内容

- 建立统一 `PackageExpander`，先将包范围和包目标转换为 canonical 活动及状态，再生成不可变求解快照。
- Planner A* 和 GA 直接消费展开后的 Planner `Scenario`。
- 旧引擎适配器将每个显式状态编译为布尔事实：
  - `required` 表示执行前必须存在且完成后保留；
  - `transition` 表示执行前必须存在并在完成时移除；
  - 主输出和附加输出在完成时激活；
  - 禁止目标编译为最终非激活；
  - 容量资源、事件最早时间、`max_steps/max_instances` 映射到旧引擎支持项。
- 旧引擎、A* 和 GA 输出统一转换为 Planner `CandidatePath`，统一执行重放、目标检查、指标计算和错误诊断。
- 新增 Planner 求解页面，支持 `LEGACY`、`ASTAR`、`GA` 和 `ALL`；`ALL` 使用同一快照独立运行，不共享候选或上界。

### 8.2 Gate P4：同输入可求解（G0）

- 三种引擎使用同一个场景快照哈希，运行记录可以证明没有按引擎生成不同业务输入。
- 所有对外展示的候选方案均通过 Planner `ResultValidator` 重放；未通过结果不得进入正式方案池。
- 活动包和状态包不会出现在任何计划步骤中，多包复用活动不会被重复实例化，除非活动规则本身允许重复执行。
- 线性、状态往返、并行资源、事件等待、包目标和多提供者黄金场景均至少被适用引擎求解并正确解释。
- 相同合法活动序列在旧引擎与 Planner 中产生一致的最终状态；无法表达的旧能力必须在求解前被公共子集校验阻止。
- 一个引擎失败、超时或无解不会丢失其他引擎已经验证的结果，状态语义可区分错误、超时、部分结果和已证明不可行。

### 8.3 Gate P4：对比可信（G1）

- 结果页面展示引擎来源、快照哈希、活动实例、时间、目标检查、等待、资源使用和 Validator 状态。
- 固定 GA 随机种子可复现；A* 与 GA 不共享随机状态、候选、上界或访问表。
- 对比模式记录首解时间、最终最好指标、合法结构数和失败诊断。

**门禁证据：** 同快照运行记录、三引擎端到端测试、统一重放报告、失败隔离测试。

## 9. P5：导入导出、旧数据迁移与兼容

### 9.1 工作内容

- JSON 导出包含活动包及系统派生的状态包，状态包标记为 `managed_by: activity_package_mirror`。
- 普通导入允许省略技术 ID 和整个状态包部分；系统生成 ID 并重写所有引用。
- 完整导出回导时可保留合法 ID；导入器以活动包侧为权威，发现镜像状态包不一致时拒绝导入，不静默修复。
- Excel 使用 `A001/P001` 等临时行引用，不把它们作为求解身份；只提供活动包、活动、前置、资源、事件和目标等可编辑工作表，状态包只在预览结果中展示。
- 旧数据迁移规则：
  - 一级/二级 `ActivityNode` 转为活动包；
  - `ActivityPackageAtomicRef` 转为活动成员引用；
  - `AtomicActivity` 转为 Planner 活动并生成主完成状态；
  - 可适配的旧输出转为附加输出；
  - 镜像状态包从新活动包和主输出重新生成；
  - 不满足公共子集的数据保留在旧表并进入阻塞或降级报告。
- 迁移过程分为预览、确认、执行和复核，执行前必须有数据库备份或可恢复快照。

### 9.2 Gate P5：数据可迁移（G0）

- 无 ID JSON、完整 JSON 和 Excel 均可导入同一黄金场景，引用解析后通过统一校验。
- JSON 导出→导入→再导出的规范化业务内容一致，允许时间戳和展示顺序等非语义字段不同。
- 恶意或错误镜像、重复 ID、悬空临时引用、跨场景成员和循环包层级均被拒绝。
- 迁移预览的创建、复用、跳过、阻塞数量与执行结果一致；任何不支持字段都出现在报告中。
- 迁移失败整体回滚，旧数据保持可读；恢复演练成功。
- 迁移前后选定公共子集场景的目标展开和合法路径语义一致。

**门禁证据：** 导入导出往返报告、迁移预览与执行对账、恢复演练记录、旧新结果对照。

## 10. P6：系统联调与发布收口

### 10.1 工作内容

- 完成后端、前端、数据库和三引擎的全量回归。
- 对典型规模场景记录建模、画布、包展开、首解和完整运行性能，不将实验值声明为生产 SLA。
- 完成部署升级、数据备份恢复、故障排查、已知限制和回退说明。
- 更新用户说明，使用业务名称解释活动、活动包、目标和依赖，不要求用户理解隐藏状态包。
- 对最终构建产物进行知识版本功能扫描和公共能力边界扫描。

### 10.2 Gate R：发布总门禁（G0）

以下条件必须全部通过：

1. Gate P0 至 Gate P5 的 G0 项全部关闭，没有借用豁免进入发布。
2. Planner 原有 64 项测试、适配新增测试、后端集成测试、前端组件测试、端到端测试和生产构建全部通过。
3. 新建场景可以在不输入任何技术 ID 的情况下完成建包、建活动、连依赖、设包目标并运行旧引擎/A*/GA。
4. 活动包目标实际展开为全部启用成员完成状态；多包复用按 canonical ID 去重。
5. 画布只有活动节点，活动包只作为容器，状态和状态包均不显性显示。
6. 所有引擎使用同一输入快照，所有正式结果通过统一 Validator。
7. 数据迁移、回滚和恢复证据完整，不支持内容有明确报告。
8. 代码、路由、菜单、接口和构建产物中不存在面向用户的知识版本功能。
9. 阻断级安全、数据一致性和事务问题为零；已知 G1/G2 项有明确记录。
10. 产品、开发和测试依据本文件签署最终验收结论。

## 13. 已锁定默认决策

- 使用指定无知识版本功能的 Git 基线，并在独立工作树开发。
- 活动和活动包采用 UUID 技术身份及场景内递增展示编号，均由后端生成。
- 活动包和隐藏状态包采用共享 UUID 后缀的一一镜像关系。
- 包层级固定为两级；活动可多包复用，包本身只有一个父级。
- 镜像状态包只包含成员活动的主完成状态；附加输出不自动成为包完成目标。
- 活动包目标要求全部启用成员活动完成，递归展开并按 canonical ID 去重。
- 网络编辑器只有活动节点，活动包是容器，状态和状态包不显性显示。
- 两套求解体系共用同一 Planner 场景快照、包展开结果、指标和结果校验器。
- 不支持的数据必须在导入、迁移或求解预检阶段明确阻断，不做隐式降级。
