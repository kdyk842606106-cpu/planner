# 自主路径探索双引擎验证需求基线

**文档编号：** APR-VP-REQ-001  
**版本：** V1.0  
**状态：** 验证基线  
**发布日期：** 2026-08-14  
**适用项目：** `planner` 自主路径探索验证项目

> 本文档是验证阶段的唯一需求基线。后续设计、开发、测试和验收均应引用本文档中的需求编号。实现方案与本文档冲突时，以本文档为准；需求变更必须更新版本、变更记录和受影响的验收项。

## 1. 文档目的

本项目用于快速验证一种区别于现有“Pathfinder 先确定路径、Scheduler 再对固定路径排程”的方案：在统一的状态、活动、时间、物料、资源和日历语义下，同时运行 Anytime A* 与遗传算法（GA）两个独立求解引擎，生成多条可行活动执行方案，并通过统一校验和对比报告评估两类算法对当前业务问题的适用性。

验证阶段关注的是算法可行性和业务表达能力，不以建设生产系统为目标。

## 2. 背景与问题定义

给定当前状态和目标状态，同一个目标可能通过不同活动组合达到。活动没有预定义的“方案归属”；执行顺序由活动前置状态、活动效果、物料到达、资源、日历和工期共同决定。

典型的模块 X 延期场景存在两类合法方案：

1. 等待模块 X 到达，安装后再上电和调测。
2. 在等待窗口内先执行不依赖 X 的工作，之后下电、安装 X、再次上电并完成剩余工作。

现有先路径后排程的单向流程难以让时间条件反向影响活动集合选择。本项目需要验证：基于事件驱动仿真和状态空间探索，是否能够自主生成上述不同结构的路径，并对其时间和业务指标进行一致比较。

## 3. 验证目标

### 3.1 核心验证问题

- **VQ-001：自主生成。** 系统能否在没有预定义 Route 或方案标签的情况下组合基础活动并达到目标状态。
- **VQ-002：时间参与选择。** 物料可用时间、资源和日历能否影响最终活动集合，而不只是影响固定活动集合的开始时间。
- **VQ-003：复杂状态过程。** 系统能否表达状态往返、等待、并行和同一活动定义的重复实例化。
- **VQ-004：双引擎适用性。** 在相同输入、约束、目标和预算下，Anytime A* 与 GA 在首解、质量、多样性、稳定性和资源消耗方面分别表现如何。
- **VQ-005：结果可信。** 所有候选方案能否被独立重放和验证，并能说明活动选择、等待及失败原因。

### 3.2 验证成功定义

满足以下条件时，本轮验证视为成功：

1. 模块 X 黄金场景能够生成并完整重放合法计划。
2. 双引擎能够在同一不可变知识快照上独立运行。
3. 至少一个引擎能够发现“等待后安装”和“等待期间提前作业”两种不同结构；另一个引擎的覆盖情况必须被如实记录。
4. 每个输出方案均包含活动执行实例、时间、偏序关系、状态轨迹、目标检查和指标。
5. 系统能够生成可重复的算法对比报告，而不是只展示单个最好结果。
6. 验证结论能够支持后续决定：选择单一主算法、保留双引擎组合，或停止该技术路线。

## 4. 范围

### 4.1 本期范围

- 基础活动定义及状态前置、增加效果和删除/覆盖效果。
- 当前状态、部分目标状态和禁止状态条件。
- 活动工期、物料最早可用时间、资源容量和工作日历。
- 状态往返和有上界的重复活动实例化。
- 事件驱动的串行与有限并行仿真。
- Anytime A* 与 GA 独立、并行执行。
- 统一结果校验、结构去重、指标计算和算法对比。
- 模块 X 黄金场景、小规模随机性质测试和基础规模摸底。
- 任务提交、进度查询、当前结果查询、停止和最终结果查询的最小 API。

### 4.2 非本期范围

- 执行过程中的实时状态采集和动态重排。
- 设备控制或活动自动下发。
- 从历史数据自动学习活动定义、规则、工期或算法参数。
- 生产级用户、角色、权限、审计和多租户。
- 跨项目资源统筹、复杂供应链和采购计划。
- 鲁棒排程、随机工期和概率型物料到达。
- 完整生产界面、复杂甘特图编辑和人工调整闭环。
- GA 使用 A* 种子、双引擎互相交换最优解等协作式求解。
- NSGA-II 等复杂多目标算法；本期只预留接口并使用统一的单一排序规则。
- 对所有业务规模证明全局最优或证明不可行。

## 5. 术语与概念

| 术语 | 定义 |
|---|---|
| Activity Definition | 活动定义。描述前置状态、效果、工期、资源、物料、日历和重复规则，不代表某次具体执行。 |
| Activity Execution | 活动执行实例。同一活动定义可以在一个计划中出现多次，每次具有独立实例编号和时间。 |
| State Fact | 状态事实，采用“状态维度=值”的枚举域表达。一个有效状态中同一维度只能有一个当前值。 |
| SimState | 搜索与仿真状态，至少包含事实、当前时间、在途活动、资源占用、物料、执行次数和执行历史。 |
| PathSimulator | 唯一运行期约束解释器，负责合法动作、事件推进和状态变化。 |
| ResultValidator | 最终结果校验器，负责对候选计划进行严格重放，不采信搜索引擎的自报合法性。 |
| Structural Path | 按活动实例、重复模式和关键偏序关系识别的路径结构，不因少量时间差异而变成新路径。 |
| Schedule Variant | 相同结构路径下不同开始时间、资源实例或并行安排形成的排程变体。 |
| Comparison Run | 两个引擎基于同一输入快照和对照预算完成的一次独立对比实验。 |

## 6. 总体原则

- **PR-001 单一语义来源：** 约束解释只能存在于知识层、PathSimulator 和 ResultValidator；搜索引擎不得复制业务约束判断。
- **PR-002 算法独立：** 对比模式下 A* 与 GA 不共享候选方案、当前上界、随机状态、支配表或访问表。
- **PR-003 输入一致：** 两个引擎必须使用同一不可变知识快照、初始状态、目标、目标函数和配置版本。
- **PR-004 输出一致：** 两个引擎必须输出同一领域契约，结果校验、指标计算和去重逻辑完全一致。
- **PR-005 先验证后生产化：** 所有设计优先满足可测、可比较和快速迭代，不提前建设非本期能力。
- **PR-006 不夸大结论：** 超时未找到方案不等于业务不可行；启用加权、Beam 或裁剪后不得宣称全局最优或已证明无解。

## 7. 最小数据需求

### 7.1 活动定义

- **DATA-001：** 每个活动定义必须具有稳定 ID、名称、前置状态、效果和工期。
- **DATA-002：** 活动效果至少支持对枚举状态维度进行设置或删除/覆盖。
- **DATA-003：** 活动可以声明零到多个资源需求，每个需求包含资源类型和数量。
- **DATA-004：** 活动可以声明零到多个物料需求；验证阶段至少支持物料最早可用时间。
- **DATA-005：** 活动可以关联工作日历；缺失时使用场景默认日历。
- **DATA-006：** 活动可以设置最大实例数和可选冷却时间；允许重复时必须有有限上界。
- **DATA-007：** 活动定义不得携带“方案一”“提前活动”等预定义路径归属。

### 7.2 状态、目标与外部条件

- **DATA-008：** 状态采用不可变、可哈希的规范化表示；同一状态维度不得同时存在多个值。
- **DATA-009：** 目标支持部分状态匹配，即未声明的状态维度不参与目标判断。
- **DATA-010：** 目标可选声明禁止事实；禁止事实在最终状态中不得成立。
- **DATA-011：** 资源必须包含类型、容量和可选日历。
- **DATA-012：** 物料必须包含稳定 ID 和最早可用时间；数量消耗不作为本轮必需能力。
- **DATA-013：** 每次求解必须记录完整输入快照 ID 或内容哈希，保证结果可复现。

### 7.3 数据预检

- **DATA-014：** 求解前必须检查未知状态维度、同域多值、悬空前置、无生产者目标事实、非法工期和非法重复上限。
- **DATA-015：** 预检发现阻断问题时不得启动算法，并应返回稳定的问题代码、对象 ID 和说明。

## 8. PathSimulator 需求

### 8.1 核心行为

- **SIM-001：** PathSimulator 必须是两个算法共同使用的唯一运行期约束解释器。
- **SIM-002：** Simulator 必须能够从事实和计划起始时间创建初始 SimState。
- **SIM-003：** Simulator 必须枚举当前可以启动的活动实例、可推进的下一事件以及显式等待动作。
- **SIM-004：** 活动启动时校验前置状态、物料、资源、日历、重复上限和冷却时间。
- **SIM-005：** 活动效果默认在活动结束事件生效，不得在活动刚开始时提前改变状态。
- **SIM-006：** Simulator 必须显式维护正在执行的活动和资源占用，支持多个不冲突活动并行执行。
- **SIM-007：** 当没有活动可立即启动但存在未来物料、资源释放或日历事件时，Simulator 应允许推进到下一事件时间。
- **SIM-008：** Simulator 不得在等待期间自行选择并自动启动业务活动；是否启动活动必须由 A* 分支或 GA 决策策略决定。
- **SIM-009：** 每次状态迁移必须产生可追踪事件，包括动作、时间、前后事实差异和触发原因。
- **SIM-010：** 当达到目标、确认死路、达到重复上限或触发安全上限时，Simulator 必须返回明确终止原因。

### 8.2 并发与状态冲突

- **SIM-011：** 两个活动并行执行前，必须检查资源容量和状态写冲突。
- **SIM-012：** 对同一状态维度产生不兼容效果的活动不得无序并行；验证阶段可采用保守策略强制排序。
- **SIM-013：** 活动前置条件在启动时校验；如业务场景要求执行期间持续成立，应作为后续扩展，不进入本轮。
- **SIM-014：** 偏序因果信息应在执行过程中记录，不得只依赖事后按时间邻近猜测。

### 8.3 不变量

- **SIM-015：** `enabled_actions` 返回的每个动作执行后必须得到合法状态或明确的并发竞争拒绝，不得静默产生非法状态。
- **SIM-016：** 任意完整仿真必须以达到目标、死路、预算终止或错误之一结束。
- **SIM-017：** 相同输入状态与相同动作必须产生相同输出状态。
- **SIM-018：** 输入 SimState 不得被原地修改。

## 9. Anytime A* 引擎需求

- **ASTAR-001：** A* 必须只通过 PathSimulator 获取合法动作和执行状态迁移。
- **ASTAR-002：** 引擎采用可配置的加权启发式搜索，并能够在找到首解后继续搜索改进解和其他结构方案。
- **ASTAR-003：** 启发函数接口必须独立，缺省实现至少考虑剩余目标事实的松弛代价。
- **ASTAR-004：** 必须支持事实、时间、资源占用、在途活动和重复计数等完整状态的去重与支配判断。
- **ASTAR-005：** 支配规则不得仅依据最终事实集合，否则会错误删除具有不同时间、资源或重复机会的状态。
- **ASTAR-006：** 必须支持时间、节点数、开放列表大小和方案数量预算。
- **ASTAR-007：** 开放列表超限时可启用 Beam 裁剪，但结果必须标记搜索不完整。
- **ASTAR-008：** 引擎必须持续向自身独立方案池发布已校验前候选，并记录发现时间和当时指标。
- **ASTAR-009：** 输出诊断至少包含扩展节点数、峰值开放列表、Simulator 操作数、首解时间、剪枝统计和最近目标差。
- **ASTAR-010：** 只有未加权且未裁剪的搜索完整穷尽状态空间时，才允许返回 `PROVEN_INFEASIBLE`。

## 10. 遗传算法引擎需求

- **GA-001：** GA 必须只通过 PathSimulator 将个体解码为活动决策和计划结果。
- **GA-002：** 验证阶段基因至少表达活动优先级、等待偏好和并行启动偏好；基因结构必须支持固定随机种子复现。
- **GA-003：** GA 不得使用 A* 的路径作为种子，不得读取 A* 当前最好结果。
- **GA-004：** 初始种群、选择、交叉、变异和精英保留参数必须配置化并写入运行快照。
- **GA-005：** 个体解码到死路时必须产生明确失败原因和惩罚，不得伪造完成计划。
- **GA-006：** 适应度必须由统一指标模块计算，不得在 GA 内另写一套业务目标。
- **GA-007：** 必须支持时间、代数、个体评估数和方案数量预算。
- **GA-008：** 必须持续归档合法且结构独特的方案，并记录首次发现时间。
- **GA-009：** 同一场景必须支持多个固定随机种子批量运行，用于评估结果波动。
- **GA-010：** GA 未找到方案时只能返回 `TIMEOUT_EMPTY` 或 `EXHAUSTED_EMPTY`，不得返回已证明不可行。

## 11. 双引擎编排需求

- **ORCH-001：** 一次 Comparison Run 必须并行启动 A* 与 GA 两个独立进程或隔离 Worker。
- **ORCH-002：** 两个 Worker 必须同时获得同一输入快照和统一截止时间。
- **ORCH-003：** 应为两个 Worker 配置明确的 CPU、内存和线程配额，避免不受控资源竞争。
- **ORCH-004：** 对比模式下两个 Worker 不得共享可变运行状态。
- **ORCH-005：** 任一 Worker 产生中间方案时，接口层应能够查询，但不得把该方案反馈给另一个 Worker。
- **ORCH-006：** 用户停止任务时，系统应请求两个 Worker 安全停止，并保留已经通过校验的结果。
- **ORCH-007：** 一个 Worker 失败不得导致另一个 Worker 的有效结果丢失。
- **ORCH-008：** 编排层必须分别保存引擎状态、错误和资源统计，并生成总运行状态。

## 12. 统一目标与排序需求

### 12.1 验证阶段统一目标

两个算法必须使用同一词典序目标：

1. 必须通过最终目标校验。
2. 最小化完工时间 `makespan`。
3. 最小化未被目标或后续前置所需的额外活动实例数。
4. 最小化状态往返次数，验证阶段重点统计上下电循环。
5. 最小化总等待时间。

- **OBJ-001：** 指标计算必须独立于搜索引擎，由统一模块完成。
- **OBJ-002：** 词典序比较必须使用明确字段，不得依赖算法内部的不可比较分值。
- **OBJ-003：** GA 可以使用归一化标量作为适应度，但最终排序必须重新使用统一词典序。
- **OBJ-004：** 所有归一化范围、惩罚值和权重必须记录在算法运行快照中。

## 13. ResultValidator 需求

- **VAL-001：** 所有候选计划在进入正式方案池前必须经过 ResultValidator 完整重放。
- **VAL-002：** 校验器必须检查活动实例身份、时间合法性、前置条件、效果、物料、资源、日历、重复规则和最终目标。
- **VAL-003：** 校验器必须检查偏序图无环，并验证所有已声明因果边与执行时间一致。
- **VAL-004：** 校验器必须从初始状态重新计算状态轨迹，不得直接信任搜索引擎输出的轨迹。
- **VAL-005：** 校验失败必须返回稳定错误代码、活动实例、时间点及相关状态差异。
- **VAL-006：** 校验器不得依赖 A* 搜索节点、GA 基因或算法私有数据。

## 14. 路径归档与去重需求

- **ARC-001：** A* 和 GA 分别维护独立原始方案池，统一归档层保留算法来源和运行来源。
- **ARC-002：** 结构路径指纹必须考虑活动定义、实例次数和关键偏序边，不得只使用活动集合。
- **ARC-003：** 相同结构但不同资源或时间安排应归为同一结构路径下的排程变体。
- **ARC-004：** 合并后不得丢失“由哪个算法、哪个随机种子、何时首次发现”的来源信息。
- **ARC-005：** 最终输出应优先展示指标较优且结构不同的方案，而不是大量微小时间差异的重复方案。

## 15. 输出契约

### 15.1 运行结果

Comparison Run 状态至少包括：

- `RUNNING`
- `OK`
- `TIMEOUT_PARTIAL`
- `TIMEOUT_EMPTY`
- `PROVEN_INFEASIBLE`
- `ERROR`
- `CANCELLED_PARTIAL`

### 15.2 单条方案

每条方案必须包含：

- **OUT-001：** 方案 ID、结构指纹、算法来源、运行 ID 和随机种子。
- **OUT-002：** 活动执行实例列表，包括实例序号、活动定义、开始时间、结束时间和点火原因。
- **OUT-003：** 偏序边，并区分状态因果、资源互斥、物料/时间和保守冲突边。
- **OUT-004：** 从初始状态开始的状态变化轨迹。
- **OUT-005：** 使用资源、物料可用条件和等待区间。
- **OUT-006：** `makespan`、总等待、活动实例数、状态往返次数和资源峰值。
- **OUT-007：** 最终目标逐项检查及整体 `goal_check`。
- **OUT-008：** 未被使用的活动定义列表。
- **OUT-009：** Validator 状态和校验版本。

### 15.3 对比报告

- **CMP-001：** 报告必须分别展示两个算法的首解时间、首解质量和最终最好质量。
- **CMP-002：** 报告必须展示随时间变化的当前最佳值和合法方案数量。
- **CMP-003：** 报告必须展示 Simulator 操作数、CPU 时间、墙钟时间和峰值内存。
- **CMP-004：** 报告必须展示独特结构数、共同发现的结构和各算法独有结构。
- **CMP-005：** GA 必须展示不同随机种子的均值、最好、最差和离散程度。
- **CMP-006：** 报告必须明确说明搜索是否完整、是否启用加权或 Beam，以及结论限制。

## 16. 最小接口需求

- **API-001：** 提交 Comparison Run，输入场景、起始状态、目标、算法配置和预算。
- **API-002：** 查询总进度及两个 Worker 的独立进度。
- **API-003：** 查询当前已经通过校验的方案快照。
- **API-004：** 请求停止运行并获取已完成结果。
- **API-005：** 查询最终方案、算法统计、对比报告和诊断。
- **API-006：** 验证阶段可使用内存或文件持久化，不强制引入数据库。

## 17. 模块 X 黄金场景

### 17.1 最小活动定义

黄金数据至少包含：

- 上电：要求系统处于下电，效果为上电。
- 下电：要求系统处于上电，效果为下电。
- 安装 X：要求模块 X 已到货且系统下电，效果为 X 已安装。
- 功能 A 调测：要求系统上电，不要求 X 已安装，完成后记录 A 已调测。
- 功能 B 调测：要求系统上电且 X 已安装，完成后记录 B 已调测。

目标状态至少要求：X 已安装、A 已调测、B 已调测，并明确最终供电状态要求。

### 17.2 预期路径结构

- **路径结构 A：** 等待 X 到货 → 安装 X → 上电 → A/B 调测 → 达到目标。
- **路径结构 B：** 上电 → A 调测 → 下电 → 等待 X → 安装 X → 再次上电 → B 调测 → 达到目标。

### 17.3 验收要求

- **ACC-X-001：** 两种结构均可由相同活动定义库产生，不得设置方案标签。
- **ACC-X-002：** 两种结构均通过 ResultValidator 完整重放。
- **ACC-X-003：** 路径 B 中上电活动必须形成两个不同执行实例。
- **ACC-X-004：** 安装 X 不得早于物料 X 可用时间。
- **ACC-X-005：** A 调测允许在 X 安装前执行，B 调测不得在 X 安装前执行。
- **ACC-X-006：** 最终结果必须明确展示等待区间、状态往返和目标检查。
- **ACC-X-007：** 两个算法都必须在固定预算下独立运行；至少一个算法发现两种结构，另一算法的发现情况记录在对比报告中。
- **ACC-X-008：** 调整 X 到货时间后，路径排序应能够发生可解释变化。

## 18. 测试需求

### 18.1 单元与性质测试

- **TEST-001：** Simulator 的确定性、输入不可变和动作合法性不变量。
- **TEST-002：** 效果只在活动结束时生效。
- **TEST-003：** 物料、资源和日历共同决定最早启动时间。
- **TEST-004：** 同维度冲突写入不得无序并行。
- **TEST-005：** 重复实例计数和上限正确。
- **TEST-006：** 小规模随机场景通过完整枚举对照合法路径和 A* 最好结果。
- **TEST-007：** GA 在相同随机种子和配置下可复现。
- **TEST-008：** Validator 能拒绝前置错误、时间穿越、资源超限、非法效果和错误目标声明。

### 18.2 集成与回归测试

- **TEST-009：** 模块 X 端到端黄金测试。
- **TEST-010：** 两个 Worker 的进程隔离和停止测试。
- **TEST-011：** 一个 Worker 失败时另一个 Worker 结果仍可返回。
- **TEST-012：** 固定场景、固定预算、固定随机种子的回归基准。
- **TEST-013：** 对比报告中的数量和指标可由原始事件日志重新计算。

## 19. 验证阶段质量要求

- **NFR-001 可复现：** 输入快照、代码版本、算法配置和随机种子完整记录。
- **NFR-002 可中断：** 运行必须支持安全停止，并保留已经校验的结果。
- **NFR-003 可观察：** 至少记录节点展开、个体评估、仿真操作、方案发现、校验失败和资源使用事件。
- **NFR-004 隔离性：** 双引擎运行时不得修改知识快照或彼此运行状态。
- **NFR-005 安全上限：** 状态数、重复实例、事件数、内存和运行时间必须有配置上限。
- **NFR-006 快速启动：** 验证环境应支持使用文件场景直接运行，不依赖完整生产数据库和前端。
- **NFR-007 结果完整：** 任何对外展示的计划必须通过 Validator。

本阶段不设生产 SLA。模块 X 场景的默认单次墙钟预算建议为 60 秒，两个算法并行使用相同截止时间；该值属于实验配置，不是业务性能承诺。

## 20. 里程碑与交付物

### M1：统一语义地基

交付：最小数据模型、场景文件、PathSimulator、ResultValidator、模块 X 手工决策重放。

退出条件：两种模块 X 结构均可通过手工动作序列生成并验证。

### M2：双引擎独立求解

交付：Anytime A* Worker、GA Worker、并行 Orchestrator、独立方案池、中间结果查询。

退出条件：两个 Worker 在同一场景上独立运行，结果互不影响，任何合法结果均可重放。

### M3：对比与结论

交付：统一指标、结构去重、对比报告、多随机种子运行、规模摸底报告。

退出条件：对模块 X 和至少一个接近真实规模的场景形成可重复对比结论。

## 21. 最终验收门槛

验证版本交付必须满足：

1. `DATA-014` 数据预检能够阻止明显错误输入。
2. `SIM-001` 至 `SIM-018` 中所有必需不变量有自动化测试。
3. A* 与 GA 在对比模式下不存在结果、种子或上界共享。
4. 所有正式候选方案通过 `VAL-001` 至 `VAL-006`。
5. 模块 X 满足 `ACC-X-001` 至 `ACC-X-008`。
6. 对比报告满足 `CMP-001` 至 `CMP-006`。
7. 超时、取消、无结果和已证明不可行具有不同状态语义。
8. 能够根据报告作出明确的后续算法路线决策。

## 22. 决策记录

### 已锁定决策

- 双引擎并行独立运行，而不是 A* 结束后再启动 GA。
- PathSimulator 是搜索过程中的唯一运行期约束解释器。
- ResultValidator 对最终输出进行独立重放。
- 活动效果默认在活动结束时生效。
- 等待只推进到决策事件，不自动替用户选择并启动活动。
- 本期使用统一词典序目标，不实施 NSGA-II。
- 模块 X 是首个端到端黄金场景。

### 后续版本可重新评估

- 是否保留双引擎生产组合。
- GA 是否使用 A* 种子或共享上界。
- 是否引入多目标帕累托求解。
- 是否支持消耗型物料数量和补货事件。
- 是否支持执行期间必须持续成立的状态条件。
- 是否将最佳方案交给独立 CP-SAT Scheduler 做二次精排。
